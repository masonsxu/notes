## 一、调研维度：跟进行业，保持口径新鲜

**用途**：知道行业现在到哪了、谁在领先、哪些数字能引用。

**材料与用法**

1. `HBM3E_HBM4E_工艺调研.md` —— 主文档。先读 §1 结论摘要表，再按需查 §2/§3 工艺细节、§3.5 时间线。
2. `sources/` —— 证据层。主文档每个数字都指向这里的具体摘录，引用前回溯。
3. `数据核对与落地评估报告.md` —— 口径定稿。§2 是"哪些原来说法被推翻"，§7 是核对依据来源。

**口径三档规则（引用纪律）**

- 官方确认（厂商新闻稿/JEDEC/财报会）→ 可进汇报正文
- 业界口径（分析机构/媒体，未经厂商证实）→ 必须加注
- 传闻（单一信源/标题级）→ 不上会

**维护节奏**：每月过一遍工艺调研的"可信度分级"区，过期数字降档或删除；重大事件（送样/量产/JEDEC 新标准）即时更新。当前遗留待核清单见核对报告 §6（ISSCC 论文卷号、WM-811K 批数两处需人工定谳）。

## 二、学习维度：从互联网背景补半导体基础

**用途**：用最快速度建立能听懂会议、能回答追问的知识底座。

**学习路径（按序）**

1. **先背下面的概念速查表**（10 分钟）
2. `HBM先进封装工艺图解.html` —— 全流程可视化，九步各干什么、哪步是良率枢纽（堆叠键合）
3. `HBM3E_HBM4E_工艺调研.md` §1 结论摘要 + §4 对照表 —— 世代差异的量化感觉
4. `先进封装测试数据分析报告.html` —— 方法论主线：统计筛查是基线、机器学习挣增量
5. `../../ideas/2026/predc-bin-feature-analysis.md` —— 动手：跑一遍 bin 特征分析（数据是 mock，方法是真的）

**概念速查表（互联网类比版）**

| 术语 | 一句话 | 类比 |
|---|---|---|
| HBM | 把 DRAM 裸片垂直堆叠、超宽接口（1024/2048-bit）的高带宽内存 | 不靠提频、靠加宽总线 |
| TSV | 硅通孔，裸片间垂直导电的"过孔" | PCB 过孔做进硅片里 |
| 微凸点 / Hybrid Bonding | 裸片间互连的两代方案：微凸点（焊球，pitch ~30μm）→ 直接铜-铜键合（<10μm） | 插针插座 → 焊接一体化 |
| WOW / DOW | 整片晶圆对键合 vs 逐颗裸片贴装 | 批量镜像部署 vs 单件流水线；区别在报废粒度 |
| MR-MUF / TC-NCF | 两大键合工艺路线（SK 海力士 vs 三星）：批量回流灌胶 vs 逐层贴膜热压 | 两种"点胶+回流"封装配方 |
| KGD / KGSD | 已知好裸片 / 已知好堆栈——堆叠前全检、堆叠后全测 | 入库全检，因为装完没法返工 |
| CP / FT | 晶圆级测试 / 封装后终测 | 集成测试 vs 系统测试 |
| ATE | 自动测试机（泰瑞达、爱德万等） | 产线上的专用测试集群 |
| STDF | ATE 输出的二进制测试记录格式（Teradyne 事实标准） | 结构化二进制日志 |
| SEMI E142 | 晶圆图（wafer map）XML 标准 | 晶圆级"拓扑图"的数据格式 |
| PAT / DPAT | 统计离群剔除；DPAT 按批次重算限值 | 基于分布的异常检测 + 滚动基线 |
| GDBN | 坏邻域里的好 die 一并剔除（空间上下文） | 邻居全是故障节点，你也要怀疑 |
| 良率模型 | 缺陷密度 → 良率的函数（负二项最常用） | 错误率与请求量的 SLO 数学 |
| 良率复利 | 0.95¹⁶≈44%：16 层堆叠对单 die 良率做乘法 | 16 个 95% 可用性的服务串行 |
| 逃逸 / DPPM | 漏检缺陷流向客户，按百万分之计 | 线上事故逃过测试环境 |
| 1-10-100 法则 | 源头/内部/现场拦截成本 ≈ 1:10:100 | bug 越晚发现修复越贵 |
| 自适应测试 | 模型预测可信则跳过部分实测 | 采样 + 置信决策，省测试时长 |
| 虚拟量测 VM | 用设备传感器软测量替代抽实测 | proxy metric 全量补齐 |
| IEEE 1838 | 3D 堆叠芯片的测试访问标准 | 可测性设计的接口规范 |
| MRB | 模型评审委员会，品质主持，模型不能自批放行 | 变更审批委员会（CAB） |
| 湖仓 / medallion | bronze/silver/gold 分层 | 你已经懂的那套 |

**过关自检**：能向别人讲清这六件事，就算入门——① HBM 为什么带宽高；② 九步流程每步干什么；③ 为什么测试必须左移；④ 0.95¹⁶≈44% 意味着什么生意；⑤ PAT 和 DPAT 的区别；⑥ 我们的 90 天 MVP 具体做什么。

## 三、技术维度：把平台真正建出来

**用途**：工程实现的依据链。读的顺序就是建设的顺序。

**按建设阶段读**

| 阶段 | 读什么 | 关键产出 |
|---|---|---|
| ① 打地基 | `先进封装测试数据分析报告.html`（Fig.01 五层管道、落地五步） | 数据标准 STDF/E142 → 列存 + 特征仓，die 级主键 = 批 + 坐标 |
| ② 定架构 | `测试数据平台系统架构.html`（PART 02） | 五层架构、三区部署、组件基线、SLO（评分 API P99<1s、批表 T+1 06:00） |
| ③ 做决策 | `测试数据立项论证.html`（PART 00 §3–§5、§8） | 量级推导（10²–10³ msg/s）、ADR 三则、决策清单 D-01~D-10 当变更控制用 |
| ④ 排路线 | `未来蓝图与落地路线.html`（PART 03） | L1–L5 能力阶梯、四阶段甘特、每阶段 go/no-go |

**技术纪律（核对后新增）**

- 组件版本全部是 **2026-09 快照**（Kafka 4.x KRaft、Iceberg 1.11、Spark 4.2、Flink 2.3、Ceph RGW、PyTorch 2.14、MLflow 3.16、Prometheus 3.14、GitLab 19）——落地时以当期 LTS 重查，快照日期必须跟着文档走
- 对象存储已改选 **Ceph（RGW）**：MinIO 仓库 2026-04 归档，只可作"存量锁定+法务评估"备选
- 算法侧结论不变：PAT/DPAT 统计基线先行，任何 ML 与 DPAT 基线比增量；1e-6 失效率场景用 PR-AUC/逃逸率/误杀率，不用 accuracy
- 算法出处以核对后的为准（方法论报告页脚 A 区），已删除的失效引用不要在代码注释/文档里复活

## 四、汇报维度：向上汇报与答辩

**用途**：给公司汇报时的材料拼装顺序、引用纪律和被挑战时的应答。

**30 分钟汇报结构（每段对应的材料）**

| 段 | 讲什么 | 用哪份材料 |
|---|---|---|
| 1 | 背景与痛点：三条量化论证（逃逸成本、测试时长、人肉取数） | PART 00 §2 |
| 2 | 行业坐标：HBM3E→HBM4E 世代、我们在封测链路的位置 | 工艺调研 §1 摘要表 + 图解页 |
| 3 | 方案一页图：五层数据管道、T+0/T+1 双时延 | PART 02 架构图 |
| 4 | 验证路径：90 天 MVP（1 VM + 2 人）+ 双退出标准 | PART 00 §6 |
| 5 | 回报：ROI 三档（保守兜底）、18 个月里程碑与三条 KPI | PART 00 §7 + PART 03 |
| 6 | 组织与治理：三部门、RACI（品质握放行、模型不自批） | PART 01 |
| 7 | 风险与回退：D-01~D-10 决策清单、MVP 不达标即停止扩张 | PART 00 §8 |

**引用纪律（上会前必查）**

1. 只用"官方确认"档数字；业界口径加注，传闻不上会（规则见调研维度）
2. 所有带时点的数字（份额、Rubin Ultra 规格、组件版本、GPU 价格）标注快照日期
3. 假设值（64 台 tester、500 DPPM、¥3.5/颗、60% 取数工时）——汇报前用公司实测替换，页面上标"立项假设，以实测重校"
4. 汇报前一天把 `HBM3E_HBM4E_工艺调研.md` 的"可信度分级"区重读一遍

**答辩弹药**：`数据核对与落地评估报告.md` §4（逐项落地判定：MVP/湖仓/闭环高风险及理由）、§5（最可能被挑战的七问七答）、§6（遗留待核——被问到就答"已识别，原文核对中"）。

**一个重要口径**：自适应闭环（跳项/改限/回写 ATE）对外表述为"内部预研 + 单客户联合试点"，不讲成 18 个月内的确定交付——封测厂的放行规则在客户质量协议里，这是 OSAT 与 IDM 的本质区别。
