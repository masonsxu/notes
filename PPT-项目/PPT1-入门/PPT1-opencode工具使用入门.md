# 《opencode 工具使用入门》原始材料

> **目标受众**：完全没接触过大模型编程工具（Code Agent）的同事，此前仅使用过聊天式大模型应用（如 ChatGPT、DeepSeek 聊天等网页/App 应用）
> **核心目的**：完成从"聊天机器人"到"能动手的编程智能体"的认知跃迁，学会安装、配置、上手 opencode，当天完成第一个真实任务
> **使用方式**：本文档为 PPT 原始材料，包含所有需要呈现的内容要点和演示素材

---

## 一、认知跃迁：从聊天机器人到 Code Agent

### 1.1 你熟悉的：大模型聊天应用

聊天应用（如 ChatGPT、DeepSeek 网页版）大家已经很熟了：

- 能随时问答、头脑风暴、帮你写文案
- 但有一个根本局限：**看不见你的文件、不能改代码、不能执行命令**
- 聊完就完了——后续的动手环节，还是得你自己来

### 1.2 opencode 是什么

**opencode** 是一个开源的 **AI 编程智能体（Code Agent）**，运行在你的终端里：

- 能**读写你的项目文件**（看到真实的代码和数据，而不是你复制粘贴的片段）
- 能**执行命令**（跑脚本、装依赖、查日志）
- 能**调用工具**（联网搜索、操作文件、运行测试）
- **端到端把活干完**：从理解需求到改好代码、跑通脚本、产出文档

### 1.3 聊天应用 vs opencode 对比

| 维度 | 聊天应用 | opencode |
| --- | --- | --- |
| **上下文** | 你贴什么，它看什么 | 打开项目目录，感知整个项目的结构、代码、文档 |
| **动手能力** | 只输出文字建议 | 读写文件、执行命令、运行脚本、调用工具 |
| **产出物** | 建议、文案、代码片段 | 改好的代码、跑通的脚本、生成的文档报告 |
| **使用方式** | 网页 / App | 终端 TUI（也支持 Web 界面与命令行模式） |

### 1.4 一句话认知

> **把 opencode 当成"能动手的助理"，而不是"只会聊天的机器人"。**
> 它的价值在于基于你的真实项目把活干完，而不是给你一段泛泛的建议。

## 二、opencode 能带来什么提效

### 2.1 核心机制：上下文感知

```
在项目目录启动 opencode
        │
        ▼
opencode 读取项目结构 / 代码 / 文档 / 数据
        │
        ▼
基于真实上下文干活 —— 而不是凭空猜测
```

- 在项目目录里运行 opencode = 让它"看到"整个项目
- 这是与聊天应用最本质的区别：**它懂你的项目，不只是懂你的问题**

### 2.2 六大提效场景

| # | 场景 | 一句话指令示例 | 产出物 |
| --- | --- | --- | --- |
| 1 | **读懂代码** | "解释一下这个模块的调用链" | 结构清晰的代码讲解 |
| 2 | **改代码 / 修 Bug** | "定位并修复登录接口的超时问题" | 改好的代码 + 修改说明 |
| 3 | **写脚本 / 自动化** | "写一个脚本批量重命名这批文件" | 可直接运行的脚本 |
| 4 | **查资料 / 补时效** | "查一下这个库最新的 API 用法" | 带来源的最新资料 |
| 5 | **分析数据** | "统计这份日志里的错误码频次" | 汇总表 / 图表 / 报告 |
| 6 | **写文档 / 整理材料** | "根据这些笔记整理一份 SOP" | 结构化文档 / PPT 大纲 |

### 2.3 效率对比

| 任务 | 传统手工方式 | opencode 方式 |
| --- | --- | --- |
| 解析 100MB 日志提取错误 | 写脚本 + 调试：30~60 分钟 | 一句指令：几分钟 |
| 给陌生项目加一个功能 | 通读代码理解架构：半天 | 让它先 Plan 再 Build：几十分钟 |
| 整理会议笔记成报告 | 手动排版：1 小时 | 一句话 + 指定格式：几分钟 |

## 三、安装与启动

### 3.1 安装（任选一种）

```bash
# 方式一：官方安装脚本（推荐）
curl -fsSL https://opencode.ai/install | bash

# 方式二：Homebrew（macOS / Linux）
brew install anomalyco/tap/opencode

# 方式三：npm 全局安装
npm install -g opencode-ai
```

### 3.2 配置模型（Provider）

opencode 是 **provider-agnostic**（模型服务商无关）的工具，支持接入多家模型：

| Provider | 说明 | 配置方式 |
| --- | --- | --- |
| **Anthropic** | Claude 系列 | 设置环境变量 `ANTHROPIC_API_KEY` |
| **OpenAI** | GPT 系列 | 设置环境变量 `OPENAI_API_KEY` |
| **Google** | Gemini 系列 | 设置环境变量 `GOOGLE_GENERATIVE_AI_API_KEY` |
| **Ollama** | 本地开源模型（离线可用） | `opencode.json` 中配置自定义 provider |

> **建议**：新手阶段选一个日常够用的模型即可，不用纠结"哪个最强"；把精力放在后面几章的配置与使用手法上。

自定义 provider 示例（`opencode.json`，用于本地 Ollama 或公司网关）：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "llama3": { "name": "Llama 3" }
      }
    }
  }
}
```

### 3.3 启动：打开项目目录

```bash
# 进入你的项目目录（代码库 / 数据文件夹 / 笔记仓库均可）
cd ~/work/my-project

# 启动 opencode
opencode
```

> 启动后 opencode 以该目录为工作区——这就是"打开项目"的含义，它接下来就能读写这里的文件。

### 3.4 界面认知（TUI 快速上手）

```
┌─────────────────────────────────────────────────┐
│ 对话消息区：opencode 的回复与操作记录           │
│                                                 │
│ 输入区：在这里输入你的指令                      │
│ [ / ] 唤起斜杠命令   [ Tab ] 切换 Plan/Build   │
│ 右下角：[plan] / [build] 模式指示器             │
└─────────────────────────────────────────────────┘
```

- `/` 开头输入斜杠命令（如 `/help`、`/new`、`/sessions`）
- `Tab` 键切换 Plan / Build 模式（右下角有指示）

## 四、Plan / Build：两种核心模式

### 4.1 为什么需要模式切换

opencode 能**动手改文件**，所以必须"先想后做"：

- 直接让它动手，改错了会破坏现有代码
- 先让它展示思路，你审核通过后再动手 —— 安全又高效

### 4.2 Plan 模式：只规划，不改动

- 按 `Tab` 键进入 Plan 模式（右下角出现 `plan` 指示）
- 该模式下 opencode **只思考、拆解步骤、列出方案**，绝不修改任何文件
- 适合：复杂任务开始前，先看它的思路对不对

### 4.3 Build 模式：按确认的方案执行

- 再按 `Tab` 键切回 Build 模式
- opencode 真正执行：创建/修改文件、运行命令、验证结果
- 适合：方案确认无误后落地

### 4.4 标准工作流

```
[ 提出需求 ]
     │
     ▼
【 Plan 模式 】 拆解步骤 / 列出涉及文件 / 评估方案
     │
  （你审核方案：思路对不对？范围合适吗？）
     │
     ▼
【 Build 模式 】 创建文件 / 修改代码 / 运行测试
     │
     ▼
[ 验证结果 ]
```

### 4.5 新手建议

> 复杂任务（涉及多文件、有风险的操作）**先切 Plan 让 opencode 展示思路**，确认后再 Build。
> 简单任务（读文件、问问题）不需要切模式，直接对话即可。

## 五、AGENTS.md：让 opencode 懂你

### 5.1 为什么需要 AGENTS.md

- 每次对话 opencode 都会自动读取 AGENTS.md，作为它的"工作指南"
- 把你的**背景、专业术语、代码偏好**写进去，一次配置、永久生效
- 避免每次对话重复输入几百字的人设说明

### 5.2 项目级 AGENTS.md（团队共享）

- 位置：**项目根目录**下的 `AGENTS.md`
- 随仓库一起提交，团队所有人都生效
- 适合：项目结构说明、编码规范、领域术语、目录约定

### 5.3 全局 AGENTS.md（个人规则）

- 位置：`~/.config/opencode/AGENTS.md`
- 对所有项目生效，不随仓库共享
- 适合：你的个人偏好、跨项目通用的习惯、常用工具链约定

### 5.4 用 /init 快速创建

- 在 opencode 里输入 `/init`，会**引导式**地创建/更新 AGENTS.md
- 新手不用从零写，跟着引导填即可

### 5.5 怎么写：四段式模板

```markdown
# 角色与背景
你是一个 [部门/角色] 的 [专业身份]，负责 [主要职责]。

# 专业术语
- 术语A: 定义（避免模型按通用含义误解）
- 术语B: 定义

# 代码与输出风格
- 优先使用 [语言/框架]
- 代码必须包含 [健壮性要求]
- 回答风格：[专业 / 简洁 / 结果导向]

# 安全与约束
- 涉及 [敏感环境] 时，先确认再操作
- [其他红线]
```

### 5.6 书写建议

- 写**你自己最了解、但模型不知道**的东西：领域术语、常用命令、代码风格偏好
- 不要写废话（"你是一个 AI 助手"）——那是默认设定
- 团队先统一一份，再按个人/项目迭代

## 六、Skill：给 opencode 装外挂

### 6.1 什么是 Skill

Skill 是**打包好的专业知识 + 操作流程**，opencode 在需要时按需加载：

- 相当于给 opencode 装"外挂"——每个 Skill 教它一个专门领域的干法
- 平时不占上下文，用到时精准加载

### 6.2 如何调用

- 在对话中直接提出需求，opencode 判断是否需要加载对应 Skill
- 或在配置中显式允许 Skill 工具（见 6.4）

### 6.3 常见 Skill 示例

| Skill | 作用 | 适用场景 |
| --- | --- | --- |
| **web search** | 联网检索最新资料 | 查 API 文档、行业标准、开源项目 |
| **planning** | 结构化拆解任务 | 复杂任务先规划再执行 |
| **review** | 代码/成果审查 | 提交前自查，抓质量隐患 |
| **debugging** | 系统化排错流程 | 疑难 Bug 定位 |
| **frontend / design** | 前端与视觉设计规范 | 写页面、做 PPT、视觉统一 |

### 6.4 权限配置

在 `opencode.json` 中控制 Skill 工具的可用性：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": "allow"
  }
}
```

## 七、会话管理：控制你的上下文

### 7.1 会话（Session）概念

- **会话** = 一次连续对话的完整上下文
- opencode 在会话里记得之前的对话，可以连续多轮工作
- 但对话越长，上下文越大，响应会变慢、花费增加——所以要学会管理

### 7.2 常用会话命令

| 命令 | 别名 | 作用 |
| --- | --- | --- |
| `/new` | `/clear` | 开启新会话（清空当前上下文） |
| `/sessions` | `/resume`、`/continue` | 列出历史会话，切换/续接 |
| `/compact` | `/summarize` | 压缩当前会话上下文（保留要点、丢弃细节） |
| `/help` | — | 查看所有可用命令 |

### 7.3 继续上次会话（终端）

```bash
# 在终端里继续上一次会话
opencode attach --continue

# 指定会话继续 / 从某会话派生新分支
opencode attach --session <session-id>   # 或 --fork
```

### 7.4 什么时候用什么

| 情况 | 该做什么 |
| --- | --- |
| 任务刚结束，要开始新话题 | `/new` 开新会话 |
| 上次的活没干完，今天接着干 | `/sessions` 续接，或 `opencode attach --continue` |
| 对话很长、响应明显变慢 | `/compact` 压缩上下文 |
| 方向错了、绕了很久 | 果断 `/new`，重新描述需求 |

## 八、第一个真实任务（手把手 Demo）

### 8.1 场景

你的 Downloads 目录里有一批软件运行日志，需要快速知道**出了哪些错、各出现几次**。

### 8.2 分步指令

**第一步：打开工作目录**
```bash
cd ~/Downloads && opencode
```

**第二步：让 opencode 干活（Plan 模式先看思路）**
```
请读取当前目录下所有 .log 文件，提取其中的 Error / ERROR / 错误
行，按错误码统计出现频次，输出为 Markdown 表格。
先切到 Plan 模式，告诉我你的处理思路。
```

**第三步：确认思路后切回 Build 执行**
```
思路没问题，切回 Build 模式执行吧。
```

### 8.3 预期输出

- 每个日志文件的错误行统计
- 按频次排序的错误码汇总表
- 异常集中分布的时段/文件提示

### 8.4 要点回顾

- 用到了：打开项目目录（上下文感知）、Plan（先看思路）、Build（执行）
- 全程没有复制粘贴日志内容——它自己读的文件

## 九、权限与安全基础

### 9.1 默认机制

opencode 执行**敏感操作**（写文件、执行命令等）前会请求你批准——这是默认的安全网。

### 9.2 权限配置

在 `opencode.json` 中按需调整（`permission` 字段可精确到具体工具）：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",        // 修改文件前询问
    "bash": "ask",        // 执行命令前询问
    "webfetch": "allow"   // 联网抓取直接允许
  }
}
```

### 9.3 安全红线

- ⚠️ 涉及**生产环境、重要数据、不可逆操作**时：先 Plan 后 Build，逐条确认
- ⚠️ 拿不准的命令，先问 opencode"这条命令会做什么"
- ⚠️ 共享代码库谨慎操作，避免误改他人代码
- ✅ 个人项目、独立分支、沙盒环境可以适当放开确认，提升效率
